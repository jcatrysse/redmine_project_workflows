- Severity: major
  File: Gemfile: the deface declaration line
  Problem: The guard skips adding deface whenever any earlier Gemfile fragment declared it, without considering Bundler groups (or platforms). If an earlier plugin declares gem 'deface' only in an excluded group (e.g., group :development), this Gemfile will still skip declaring deface. In a production bundle (without :development), deface will then not be included at all, and the plugin’s Deface overrides will fail to load at boot.
  Concrete failure scenario: Another plugin earlier in load order has in its Gemfile: group :development do; gem 'deface'; end. This plugin’s Gemfile evaluates after it, sees a deface dependency and skips adding deface. The host runs bundle install --without development test, so deface is not installed/required. On boot, init.rb (or Deface usage) raises LoadError/NameError, Redmine fails to start.
  Fix: Only skip when an earlier declaration will be active for the current bundle. For example:
    gem 'deface' unless dependencies.any? do |dep|
      next false unless dep.name == 'deface'
      # consider only groups that are not excluded
      without = Array(Bundler.settings.without).map(&:to_sym)
      active_groups = dep.groups.map(&:to_sym) - without
      next false if active_groups.empty?
      # optional: also consider platforms if you use them
      true
    end
  Alternatively, simplify: always declare plain gem 'deface' and let Bundler merge duplicate identical requirements; only skip when an earlier declaration has a conflicting requirement.

Resolution: fixed in the next commit ("Act on the second OpenAI review"). The guard now only steps aside for an earlier declaration in the default group with no platform restriction; plugin_conventions_spec adds a dev-only earlier declaration and asserts deface reaches :default, red before the fix ('expected [:development] to include :default').
